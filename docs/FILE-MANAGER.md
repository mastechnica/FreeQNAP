# File manager and recycle bin

The Files workspace is a local desktop with up to eight independent folder windows. Move and resize title-bar windows, minimize to the taskbar, maximize/restore or tile them, and select Details or Icons view. Double-click opens a folder or supported media; right-click exposes file actions. Select a shared folder in each window, browse, filter names and page through results. Drag items between windows to copy; Shift-drag moves within the same filesystem. Copy/cut/paste provides a drag-free alternative. A selection can contain up to 200 items. New folders, rename, duplicate, browser upload/download, recycle, permanent deletion and recovery are available locally.

Transfers use reviewed plans bound to source identities and the destination directory/filesystem. Copies are written into a private stage on the destination volume, read back with SHA-256 verification, then published using Linux's atomic no-overwrite rename. They run as durable background jobs; watch Activity for completion. Existing targets are never replaced. Failure retains partial stages and an operation checkpoint; the recycle panel lists failed unpublished stages with a separately reviewed cleanup action that preserves originals and published files; creation/deletion/transfer jobs cannot be blindly retried. A successful copy is not a consistent snapshot of concurrently changing files.

Moves preserve existing ownership and modes. Copies create files under the destination share group (0660 files, 2770 directories); they do not promise ACL/xattr/hard-link/sparse-file preservation. Symlinks, special files, nested mounts and reserved private folders are not copied. Cross-volume moves require a successful copy and a separate reviewed recycle action. Copy trees are bounded to 64 levels and 200,000 entries. Browser uploads currently accept at most 64 GiB per file, subject to free space; use SMB/NFS or server-side copy for larger files.

## Recycle policy

Ordinary deletion moves data into the volume's private recycle area and durably records its original share/path. The default retention is **30 days**, configurable from zero (keep indefinitely) through 3650 days. A reviewed policy change applies to existing dated entries; reducing retention may cause immediate expiry at the next cleanup. The independent cleanup worker normally checks every five minutes.

Locked, missing or changed filesystems retain their data and records. Undated legacy entries and incomplete recycle mutations do not expire automatically. Recovered entries are excluded. A failed purge retains its record and any remaining data rather than claiming success. This recycle bin covers dashboard delete operations; files deleted directly by an SMB/NFS/AFP client are not automatically intercepted by it.

The recycle-bin panel offers reviewed recovery to the original folder and reviewed permanent deletion. Recovery never overwrites an existing item. A separate **Delete permanently** action bypasses the retention period only after an explicit review. Recursive deletion never follows symlinks or crosses into another mounted filesystem. Backup snapshots are independent of the recycle bin; retention expiry is not a backup policy.

## Acceptance

Host and native ARMhf tests cover recursive copy/readback, duplication, atomic no-overwrite move, stale sources, directory-into-itself refusal, symlink rejection, multi-item recycle, policy changes, expiry, offline storage retention, permanent deletion and name filtering/pagination. Linux tests use the real renameat2 primitive; the Mac uses a fixture replacement for that Linux-specific call. Physical-disk file-manager acceptance, large transfers, interruption/recovery drills and real browser drag/drop remain separate checks.

## Browser playback and downloads

Recognized video/audio files offer **Play** and raster images offer **View**. A dialog provides native playback/seek controls, fullscreen, image fit/zoom and an original-file download. Supported playback depends on the browser's codecs; there is no transcoder and an extension does not prove codec compatibility. Unsupported files remain downloadable. Active SVG/HTML content is downloaded as an attachment rather than embedded. Authenticated media requests support HEAD and single/suffix byte ranges for seeking, with source-change detection and no-store responses.

**Download selected** downloads one regular file unchanged. Multiple items or a selected directory are delivered as one ZIP64 archive. **Download folder as ZIP** includes the current folder and all descendants, including items outside the filtered or paginated display. **Select page** selects only the visible page (up to 100 entries); the maximum explicit selection is 200. Symlinks, special files, nested filesystems and overlapping selected roots are refused. Browser ZIPs stream directly through guarded reads without occupying NAS staging space. They are bounded to 200,000 entries, 64 levels and 16 TiB of input. Keep the browser connection open; ZIP streaming is not resumable. Ordinary file downloads support range requests, although automatic resumption depends on the browser. If input changes or the connection fails, discard the incomplete ZIP and retry; the writer omits the central directory after a source error.

## Create and extract archives

Select files/folders and choose **Create ZIP**. Enter a filename and output-size limit, review the plan and confirm. The background job stages the ZIP on the selected data volume, verifies every member's CRC by reading the saved archive back, then publishes it without replacing an existing file. Save outside any selected source directory. This is a convenience archive, not a substitute for the encrypted/versioned backup system.

Select one archive and choose **Extract here** or **Extract to named folder**. The latter removes the archive suffix (including `.tar.gz`) to form the folder name. Existing files are never replaced. Extraction first stages and SHA-256 verifies files on the data volume. Named-folder publication uses one atomic no-overwrite rename; current-folder publication reviews all collisions first and checkpoints each top-level rename. A race/interruption can leave some top-level items published and the rest in a retained stage; inspect Activity before taking further action.

Extraction uses Debian's `libarchive13t64` through its read API, never shell extraction or filesystem-writing libarchive calls. ZIP, tar and common gzip/bzip2/xz streams are tested; additional formats such as 7z/RAR depend on the installed library and archive variant. Password-protected archives are explicitly refused. File links, devices, absolute/parent traversal, reserved private paths, duplicate paths and nonportable names are refused. Default maximum extracted/output size is 64 GiB, selectable up to 16 TiB, subject to a 256 MiB free-space reserve. Extraction also limits entries to 100,000, depth to 64 and expansion to 10,000× (with a 1 MiB minimum allowance). Only ordinary file data and directory structure are restored, with destination share ownership/modes; ACLs, xattrs, original ownership, sparse allocation and links are not preserved.

Failed unpublished stages use the existing separately reviewed stage cleanup. Jobs do not blindly restart after interruption. Passwords/keys are not accepted by or retained in archive jobs. The native service setup checks that libarchive is installed; system package updates must keep that parser current.

## Desktop interaction and live updates

Each open, non-minimized folder refreshes every five seconds while the Files workspace and browser tab are visible. Unchanged listings do not rebuild the rows; refresh retains selection and scroll position, and a stale in-flight response cannot replace a newer folder. A failed refresh is visibly unavailable rather than an empty healthy directory. Refresh pauses during operation review. Window position, navigation and clipboard remain browser-session UI state; passwords and file contents are not stored there. There is no cloud desktop service or external JavaScript dependency.

Click selects an item; Ctrl/Cmd-click toggles, Shift-click selects a visible range. Ctrl/Cmd-A selects the current page, Ctrl/Cmd-C/X/V copy/cut/paste, Ctrl/Cmd-L focuses the address, F2 renames, Enter opens, Alt-Up goes to the parent, and Delete recycles. Shift-Delete requests permanent deletion with the existing review. Text input fields retain their normal editing shortcuts. The context menu supports arrow-key navigation and Escape. Keyboard controls never bypass backend review, mounted-share boundaries or no-overwrite safeguards.

Create a NAS user/share in **Shares & users** before browsing live data; the desktop does not silently export a volume or create a guest account. Desktop drag targets accept ordinary browser file uploads; directory-tree uploads and native operating-system clipboard integration are not promised. Copy/move, ZIP/extraction, recycle and file streaming retain their existing server-side contracts. Live physical cross-window transfers and actual client workflows still require operator acceptance; synthetic preview interactions do not prove real storage mutation.

## Drive and folder dropdowns

Each desktop window now has a **Drive or shared folder** selector and a **Folder location** selector. The sidebar lists the same locations: enabled shared folders, registered internal/USB volumes, active decrypted foreign-disk sessions and attached USB devices that need management/unlocking. Labels distinguish locked/offline locations and read-only drive views. Refresh locations runs explicitly or periodically while Files is open; changing locations resets folder history rather than carrying paths into another drive. The folder picker includes the root, current ancestors and immediate non-symlink subfolders on the visible page. The full path field remains available.

Direct registered-volume and foreign-session views support read-only navigation, supported media viewing and individual-file downloads. New folders, uploads, rename, recycle, archive creation and write/drop destinations stay disabled there. Cross-location clipboard/ZIP transfers from these direct views are not implemented; use individual downloads or a deliberately configured NAS share. Existing writable shared folders retain their reviewed copy/move, upload and drag/drop workflows. Selecting a disk never formats, unlocks, imports, mounts or exports it automatically.

Registered-volume browsing uses authenticated `files.pool-list`, `files.pool-read` and `/api/pool-file?pool=NAME&path=RELATIVE` routes. Optional `inline=1` uses existing media-kind checks and range support. These accept only existing registered pools and revalidate their filesystem/source mapping through the normal volume guard. They expose no arbitrary device/path selector or write operation. Existing external-only routes retain their external-volume restriction. Filters, bounded pagination, symlink/traversal refusal, login enforcement and media range behavior have regression tests.

### Location-selector validation

The full native suite passed 199 tests, including registered-pool read/filter/pagination, unknown-pool/traversal/symlink refusal, authenticated range streaming and public delivery of the non-sensitive selector script. Ten Node desktop/PWA/location tests passed, including clearing stale selections before a failed folder change. In the live signed-in Brave dashboard, selecting an internal data volume and navigating into a child using the folder dropdown passed with mutation controls disabled. Encrypted-session availability now revalidates the current attachment and read-only mount rather than trusting a stale mountpoint alone; reformatted/replugged disks cannot inherit the earlier session's available status. New physical Linux unlock and cross-location transfer acceptance remain separate.

USB controls use plain action labels: **Add existing volume** registers an existing filesystem without formatting; **Format drive…** opens the erase/layout confirmation; **Eject safely** opens the safe-eject confirmation. **Unlock read-only** explicitly identifies protected inspection, while registered volumes retain their selected access mode. **Lock volume** closes encryption without claiming the entire device has been ejected. The final confirmation and identity checks remain required.

USB storage now groups current volumes and unlock/mount/browse controls under their physical drive. Registered encrypted volumes show **Unlock & mount** with the selected access mode. Historical sessions and irrelevant format capability lists are omitted. Serial/connection details and registration removal are under **Drive settings…**; destructive creation is nested under **Erase and format drive…**, collapsed by default. No storage execution or confirmation rules changed.

Registered writable volumes now support administrator file operations directly through the `pool:` location, without creating a network export. The existing identity-checked descriptor traversal and no-overwrite file operations apply; read-only pools reject this write path. Context menus expose Copy, Cut / move, Rename, Duplicate, upload/paste and recycle operations on writable locations. Unlock dialogs display a busy message while waiting. Physical LUKS/ext4 validation created a folder and uploaded/read-back verified a silent WAV fixture on disposable USB media; this does not establish every transfer/archive/recovery case.
